vLLM arguments for QAIC
=======================

Unless noted otherwise, the arguments on this page apply to AoT mode. See
:ref:`PyT mode arguments <vllm_pyt_mode_args>` for the arguments and
environment variables that apply to PyT (PyTorch eager) mode.

Override Arguments that can be modified
---------------------------------------

additional-config = ``<JSON QAIC compiler configuration>``

Using this interface, users can override default attributes such as
num_cores, dfs, mos, device_group, qpc_path, mxfp6_matmul,
mxint8_kv_cache, and other compiler options. Put target-model compiler
settings under the ``override_qaic_config`` key. For SpD, put draft-model
settings under the sibling ``draft_override_qaic_config`` key.

CLI inferencing
~~~~~~~~~~~~~~~

Single space between attributes, no space within attribute and value
pair during running on command line arguments.

Example

.. code-block:: text

   --additional-config '{"override_qaic_config":{"num_cores":4,"mxfp6_matmul":true,"mos":1,"device_group":[0,1,2,3]}}'

Note: Only provide attributes which need to be overridden.

Python object inferencing
~~~~~~~~~~~~~~~~~~~~~~~~~

Override arguments can also be passed as input during LLM object
creation.

Example

.. code-block:: text

   additional_config = {
       'override_qaic_config': {
           'num_cores': 8, 'mxfp6_matmul': True, 'mos': 1
       }
   }

Note: Only provide attributes which need to be overridden.

------------------------------------

+---------------------------+-----------------------+-----------------------+
| Input Arg                 | Default Value         | Setting Required for  |
|                           |                       | Qaic runs             |
+===========================+=======================+=======================+

|                           |                       | the path to qpc. vLLM |

|                           |                       | directly from the     |
|                           |                       | path provided and     |
|                           |                       | won't compile the     |
|                           |                       | model                 |
+---------------------------+-----------------------+-----------------------+
| VLLM_QAIC_MOS             | None                  | Set MOS value         |
+---------------------------+-----------------------+-----------------------+
| VLLM_QAIC_DFS_EN          | None                  | Enable compiler depth |
|                           |                       | first                 |
+---------------------------+-----------------------+-----------------------+
| VLLM_QAIC_QID             | None                  | Manually set QID for  |
|                           |                       | qaic devices          |
+---------------------------+-----------------------+-----------------------+
| VLLM_QAIC_NUM_CORES       | None                  | Set num_cores example |
|                           |                       | 14 or 16              |
+---------------------------+-----------------------+-----------------------+
| VLLM_QAIC_COMPILER_ARGS   | None                  | Set additional        |
|                           |                       | compiler arguments    |
|                           |                       | through this          |
|                           |                       | environment variable  |
+---------------------------+-----------------------+-----------------------+
| VLLM_QAIC_MAX_CPU_THREADS | None                  | Avoid                 |
|                           |                       | oversubscription of   |
|                           |                       | CPU threads, during   |
|                           |                       | multi-instance        |
|                           |                       | execution. By default |
|                           |                       | there is no limit, if |
|                           |                       | user sets this        |
|                           |                       | environment variable, |
|                           |                       | then number of cpu    |
|                           |                       | thread running        |

|                           |                       | cpu is limited, to    |
|                           |                       | avoid                 |
|                           |                       | over-subscription.    |
|                           |                       | The contention is     |
|                           |                       | amplified when        |
|                           |                       | running in a          |
|                           |                       | container where CPU   |
|                           |                       | limits can cause      |
|                           |                       | throttling.           |

.. _vllm_pyt_mode_args:

PyT mode arguments and environment variables
--------------------------------------------

These settings apply when the plugin runs in
:doc:`PyT (PyTorch eager) mode <Execution-Modes>`.

.. list-table::
   :widths: 30 20 50
   :header-rows: 1

   * - Argument / variable
     - Default value
     - PyT mode behavior
   * - ``enforce-eager``
     - False
     - Required (``True``). If it's not set, the plugin sets it and logs a
       warning. In AoT mode the plugin forces it to ``False``.
   * - ``async-scheduling``
     - Auto
     - Not supported; set ``--no-async-scheduling`` (``async_scheduling=False``).
       If it's enabled, the plugin falls back to non-async scheduling.
   * - ``gpu-memory-utilization``
     - 0.9
     - Fraction of device memory used for the KV cache. Applies only in PyT
       mode; AoT mode sizes memory from the QPC.
   * - ``tensor-parallel-size``
     - 1
     - Number of QIDs used for vLLM tensor parallelism (for example, 4 for
       32B vision-language models).
   * - ``quantization`` / ``kv-cache-dtype``
     - "auto"
     - Leave as ``auto``. MXFP6 and MXINT8 are AoT mode only.
   * - ``QAIC_VISIBLE_DEVICES``
     - All devices
     - Comma-separated list of QIDs (for example, ``0,1,2,3``). Set it before
       importing vLLM, because ``torch_qaic`` reads it on import.
   * - ``VLLM_TORCH_QAIC_PROFILER_DIR``
     - None
     - Output directory for device-level profiling. When set, the PyT model
       runner records forward-pass latency with ``torch_qaic`` profiling.
   * - ``TORCH_QAIC_BASE_PATH``
     - ``/opt/qti-aic/integrations/torch_qaic``
     - Used only by ``scripts/install.sh pyt``. Base path of the
       ``torch_qaic`` wheels from the Apps SDK.

The AoT-only environment variables (``VLLM_QAIC_QPC_PATH``,
``VLLM_QAIC_MOS``, ``VLLM_QAIC_DFS_EN``, ``VLLM_QAIC_NUM_CORES``, and
``VLLM_QAIC_COMPILER_ARGS``) control QPC compilation and have no effect in PyT
mode.

Avoiding CPU oversubscription via VLLM_QAIC_MAX_CPU_THREADS
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

CPU oversubscription refers to a situation where the total number of
CPUs allocated to a system exceeds the total number of CPUs available on
the hardware. This leads to severe contention for CPU resources. In such
cases, there is frequent switching between processes, which increases
processes switching overhead and decreases overall system efficiency. In
containers where multiple instances of vLLM can cause oversubscription,
limiting the concurrent CPU threads is a good way to avoid
oversubscription.

Example

.. code-block:: bash

   export VLLM_QAIC_MAX_CPU_THREADS=8
   export OMP_NUM_THREADS=8

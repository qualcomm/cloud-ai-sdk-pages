    Execution Modes (AoT and PyT)¶

    The vLLM QAIC plugin (vllm-qaic) runs models on Qualcomm Cloud AI accelerators in one of two execution modes:

    • AoT (Ahead-of-Time) mode - the default, production mode. Models are exported and compiled by QEfficient and the Apps SDK into a Qualcomm Program Container (QPC), which the plugin runs on the device.

    • PyT (PyTorch eager) mode - experimental. vLLM model definitions run directly in PyTorch, and torch_qaic dispatches the operators to the device. No export or compilation step is required.

    How the mode is selected¶

    There is no mode flag. The plugin selects the mode at startup based on the Python environment:

    • If torch_qaic is not installed, the plugin runs in AoT mode.

    • If torch_qaic is installed, the plugin runs in PyT mode.

    Because the two modes need different PyTorch versions, install each mode in its own Python virtual environment. They can’t share an environment. See Build for x86_64 for installation steps for both modes.

    About torch_qaic¶

    torch_qaic is an out-of-tree PyTorch backend for Qualcomm Cloud AI accelerators. It registers the accelerator with PyTorch as the qaic device and runs PyTorch operators on the device through a just-in-time (JIT) runtime and a prebuilt operator library.

    torch_qaic ships with the Apps SDK. The installer places torch_qaic wheels for each supported Python version under /opt/qti-aic/integrations/torch_qaic/py<version>/ (for example, py312).

    Running in PyT mode¶

    PyT mode requires these engine arguments:

    • enforce_eager=True - if this isn’t set, the plugin sets it automatically and logs a warning.

    • async_scheduling=False

    gpu_memory_utilization sets the fraction of device memory used for the KV cache. It applies only in PyT mode; AoT mode sizes memory from the QPC.

    Set QAIC_VISIBLE_DEVICES before importing vLLM. Importing PyTorch autoloads torch_qaic, which reads this variable to enumerate devices.

    Offline inference example¶

    import os

os.environ.setdefault("QAIC_VISIBLE_DEVICES", "0")

from vllm import LLM, SamplingParams

llm = LLM(
    model="Qwen/Qwen2.5-VL-7B-Instruct",
    max_num_seqs=4,
    max_model_len=4096,
    gpu_memory_utilization=0.9,
    enforce_eager=True,
    async_scheduling=False,
)

    The vllm-qaic repository includes PyT mode examples:

    • examples/qaic_eager_mode.py - basic offline text generation.

    • examples/qaic_eager_mode_vision_language.py - image and video inputs for vision-language models.

    python examples/qaic_eager_mode_vision_language.py \
    --model-type qwen2_5_vl \
    --tp-size 1 \
    --image-path /path/to/image.jpg \
    --question "Describe the image."

    Online serving¶

    export QAIC_VISIBLE_DEVICES=0,1,2,3

vllm serve Qwen/Qwen3-VL-32B-Instruct \
    --host 0.0.0.0 \
    --port 8000 \
    --tensor-parallel-size 4 \
    --max-num-seqs 4 \
    --max-model-len 4096 \
    --gpu-memory-utilization 0.9 \
    --enforce-eager \
    --no-async-scheduling

    PyT mode supported models¶

    See the PyT mode section of vLLM supported models.

    PyT mode limitations¶

    PyT mode is experimental. These features are supported in AoT mode only:

    • Speculative decoding

    • LoRAX

    • Disaggregated serving

    • Quantization (MXFP6 and MXINT8)

    • Compute Context Length (CCL)

    • On-device sampling

    • Prefix caching

    In addition:

    • Text-only LLMs aren’t validated in PyT mode.

    • best_of > 1 and beam search aren’t supported.
